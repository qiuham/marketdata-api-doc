# Execution Report

> Order acknowledgements, fills, amends, cancels, expiries and engine rejects, as copied to a drop copy session

FIX
session: drop copy
35=8

Reports every state change on an order once the engine has accepted it. ExecType says what happened — new, replaced, cancelled, expired, traded, restated or rejected — and OrdStatus says what state the order is now in. Fills carry LastPx, LastQty, the running CumQty and AvgPx, the trade identifier and the maker/taker flag in LastLiquidityInd.

**Direction:** Kraken → client

***

## Differences from order entry

The Drop Copy Execution Report is the order entry Execution Report ([Execution Report](https://docs.kraken.com/exchange/api-reference/unified-fix-v2/er.md)), in the same field order and with the same values, apart from these differences:

* TradeDate (75), ClearingFirm (439) and AccountType (581) are added.
* ClOrdID (11) is the order's first ClOrdID on every report, including after an amend, on a cancel, a mass cancel and a cancel-on-disconnect. OrigClOrdID (41) is not sent.
* Numbers are rendered from the exchange's values, so trailing zeros can differ from order entry's echo of the order (`0.0` against `0`) in ClOrdID (11), OrderQty (38), Price (44), Account (1) and the New's Text (58).
* A GTC order sent with ExpireTime (126) is reported `59=6`; order entry echoes `59=1`.
* InstrumentID (48) is sent whenever the id is known. Order entry leaves it out for an order it holds without one, and names that order's New `S:<OrderID>:<time>`. Drop Copy has no report with that ExecID (17).
* Order status answers (`150=I`) are not sent.
* DisplayQty (1138) is not sent. Order entry echoes it on an order sent with one.
* No report is sent for an amend the exchange refuses on a live order, or for a cancel or amend that names no live order. Order entry answers those with a reject message, not an Execution Report.
* Header fields (SenderCompID, TargetCompID, MsgSeqNum) are those of the Drop Copy session.

***

**header** *required*

35=`8`

**37 - OrderID** `string`

Exchange-assigned order identifier generated by Kraken.

**Format:** Assigned by Kraken.

**11 - ClOrdID** `string` *required*

The order's first ClOrdID, as sent by the client, on every report for the order, including after an amend, on a cancel, a mass cancel and a cancel-on-disconnect. On US Perps it is a positive integer of at most 19 digits.

**Format:** Positive integer, up to 19 digits, e.g. a microsecond timestamp.

**41 - OrigClOrdID** `string`

Declared in the dictionary but not sent.

**17 - ExecID** `string` *required*

Unique identifier of this execution report: the ExecID that order entry sends on the same report, so a client reading both feeds can match the two. It is 27 characters long. Treat it as opaque: do not parse it or derive it from ClOrdID. It is the key to de-duplicate a report that is delivered again after a reconnect: a report delivered again has the same ExecID as the first. One report does not share its ExecID with order entry: the New of an order that order entry holds without its instrument id. Order entry names it `S:<OrderID>:<time>`, and Drop Copy has no report with that ExecID. An ExecID sent before your environment switched to this form never matches one sent after it.

**150 - ExecType** `char` *required*

Nature of the event this execution report describes.

**Possible values:**

* `0` : New - the order is live in the engine.
* `4` : Canceled - the order was cancelled.
* `5` : Replace - the amend was applied.
* `8` : Rejected - the matching engine refused an order it had already acknowledged, for example a post-only order that would cross, a fill-or-kill order that cannot be filled in full or an order stopped by market price protection. The report carries OrdRejReason (103) and Text (58).
* `C` : Expired - the order reached its expiry.
* `D` : Restated - the engine changed the order itself.
* `F` : Trade - the order got a fill. LastPx/LastQty carry that fill.

The dictionary also lists `I` (Order Status). Drop Copy never sends it.

**39 - OrdStatus** `char` *required*

Current state of the order.

**Possible values:**

* `0` : New - live, nothing filled.
* `1` : Partially filled - live with fills against it.
* `2` : Filled - fully filled and closed.
* `4` : Canceled - cancelled and closed.
* `8` : Rejected - the matching engine refused the order after acknowledging it. See OrdRejReason (103) and Text (58) for the reason.
* `C` : Expired - expired and closed.

Drop Copy never sends `39=A`.

**103 - OrdRejReason** `integer`

Code identifying the reason why an order was rejected by the matching engine. Sent on a rejected order.

**Possible values:**

* `1` : Unknown symbol.
* `2` : Exchange closed.
* `3` : Order exceeds a limit (quantity cap, price bounds and bands).
* `5` : Unknown order.
* `6` : Duplicate order.
* `11` : Unsupported order characteristic.
* `13` : Incorrect quantity.
* `99` : Other.

The other FIX 4.4 values are not sent.

Required: Conditional

**1 - Account** `string`

Numeric end-client id of the end client the order was placed for, as sent in Account (1) on the order.

**Format:** Non-zero numeric end-client id.

**581 - AccountType** `integer` *required*

Type of the account. Not on the order entry Execution Report.

**Possible values:**

* `1` : Account is carried on the customer side of the books.

**439 - ClearingFirm** `string` *required*

Clearing firm label. A fixed value set by Kraken. Not on the order entry Execution Report.

**55 - Symbol** `string`

Perpetual futures contract, in the venue symbol form. Left out, not sent as a placeholder, when the instrument cannot be resolved. InstrumentID (48) still identifies it when the id is known.

**Format:** Venue symbol.

**48 - InstrumentID** `string`

Identifier of the instrument within the Kraken instrument scheme. Sent whenever the id is known.

**Format:** Venue instrument identifier.

**54 - Side** `char` *required*

Side of the order.

**Possible values:**

* `1` : Buy.
* `2` : Sell.

**38 - OrderQty** `Qty`

Order quantity in contracts.

**40 - OrdType** `char`

Execution model of the order. Sent whenever the order is a market or limit order; left out for any other order type. Required on order entry, optional here.

**Possible values:**

* `1` : Market - fill the whole quantity immediately at the best available prices.
* `2` : Limit - rest in the book, trading only at the limit price or better.

**44 - Price** `Price`

Limit price of the order, denominated in the quote currency. Not sent on a market order.

**Format:** Limit price, denominated in the quote currency.

Required: Conditional

**59 - TimeInForce** `char`

How long the order stays in effect. A GTC order sent with ExpireTime (126) is reported as `6`; order entry echoes `1`.

**Possible values:**

* `1` : GTC - good till cancelled. Rests indefinitely.
* `3` : IOC - fill what you can immediately, cancel the rest.
* `4` : FOK - fill the entire quantity immediately or cancel the whole order.
* `6` : GTD - good till date.

**32 - LastQty** `Qty`

Quantity bought or sold on this fill. Sent on a trade.

Required: Conditional

**31 - LastPx** `Price`

Price of this fill. Sent on a trade.

Required: Conditional

**151 - LeavesQty** `Qty` *required*

Quantity still working in the book. `0` on every report that ends an order.

**14 - CumQty** `Qty` *required*

Total quantity filled on the order so far. It rises with every fill of an order.

**6 - AvgPx** `Price` *required*

Average price across all fills on the order. `0` before a fill.

**75 - TradeDate** `LocalMktDate`

UTC date of the report's event, formatted `YYYYMMDD`. Not on the order entry Execution Report.

**Format:** `YYYYMMDD`, UTC.

**60 - TransactTime** `UTCTimestamp`

Time of the business event in UTC, formatted YYYYMMDD-HH:MM:SS.uuu. On a New, the time the order arrived.

**Format:** UTC timestamp, YYYYMMDD-HH:MM:SS.uuu

**381 - GrossTradeAmt** `Amt`

Sent only on a New with no fill, as `0`.

**58 - Text** `string`

Free-text description. On a New, the order description (for example `buy 10 PBTCUCZ50 @ limit 100`) when Symbol and OrdType are known; on other reports, the reason, when there is one.

**Format:** Free text set by Kraken.

**851 - LastLiquidityInd** `integer`

Code indicating whether this fill added liquidity to or removed liquidity from the market. Sent on a trade. Only `1` and `2` are sent.

**Possible values:**

* `1` : The fill added liquidity to the order book.
* `2` : The fill took liquidity from the order book.

Required: Conditional

**1003 - TradeID** `string`

Exchange-assigned identifier of the trade. Sent on a trade.

Required: Conditional

**1138 - DisplayQty** `Qty`

Declared in the dictionary but not sent. Order entry echoes it on an order sent with one.

**trailer** *required*
