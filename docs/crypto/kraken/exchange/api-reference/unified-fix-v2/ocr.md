# Order Cancel Request

> Cancel a single working order

FIX
session: trading
35=F

Cancels one working order. At least one of OrderID (37) or OrigClOrdID (41) must identify the target; where both are present, OrderID wins. ClOrdID (11) is the identifier of the cancel request itself. On US Perps the order is looked up among the orders cached for this SenderCompID, earlier connections included, not only the orders of the current session, and Side and Symbol (or InstrumentID) must match the order. Success returns an Execution Report with OrdStatus=4. A cancel that Kraken will not act on is answered with an OrderCancelReject (35=9) or, where that is not enabled, a BusinessMessageReject (35=j); a field-level error is answered with a Reject (35=3). Clients should handle all three until the production setting is confirmed.

> [!NOTE]
>
> **Cancel: venue differences**
>
> | | US Perps | Spot | Futures |
> | :- | :- | :- | :- |
> | Which orders a single cancel reaches | Any order cached for this SenderCompID, earlier connections included; Side and Symbol or InstrumentID must match | Same cache scope; no Side or Symbol match rule | Same as Spot |
> | Cancel business reject | `35=9` (enabled in UAT; production to be confirmed) | `35=j` | `35=j` |

**Direction:** Client → Kraken

***

**header** *required*

35=`F`

**41 - OrigClOrdID** `string`

ClOrdID of the previous action on the order. On a cancel or amend it identifies the order being acted on; if OrderID is also present, OrderID takes precedence. Optional on this message: Kraken relaxes the FIX 4.4 requirement so a client may cancel by OrderID alone.

Required: Conditional

**37 - OrderID** `string`

Exchange-assigned order identifier generated by Kraken; the value to quote back on cancels, amends and status requests.

**Format:** Assigned by Kraken; quote it back on cancels, amends and status requests.

Required: Conditional

**11 - ClOrdID** `string` *required*

Client-assigned identifier of the cancel request. On US Perps it must be a positive integer of at most 19 digits: use an ever-increasing number, for example a microsecond timestamp. See [New Order Single](https://docs.kraken.com/exchange/api-reference/unified-fix-v2/nos.md) for how invalid values are rejected.

**Format:** Positive integer, up to 19 digits, e.g. a microsecond timestamp.

**1 - Account** `string`

Numeric end-client id of the end client the order belongs to. Optional on this message and not used: the end client is taken from the original order.

**Format:** Non-zero numeric end-client id.

**55 - Symbol** `string`

Perpetual futures contract, in the venue symbol form. Ten contracts are listed at launch. Either Symbol or InstrumentID must be sent. Must match the instrument of the order being cancelled. Ignored when InstrumentID is also sent: the instrument is then recognised from InstrumentID.

**Format:** Venue symbol.

Required: Conditional

**48 - InstrumentID** `string`

Identifier of the instrument within the identification scheme named by InstrumentIDSource. Either Symbol or InstrumentID must be sent.\
Where both Symbol and InstrumentID are sent, InstrumentID is what the instrument is recognised from and Symbol is ignored.

**Format:** Venue instrument identifier. Takes precedence over Symbol when both are sent.

Required: Conditional

**22 - InstrumentIDSource** `string`

Identification scheme that InstrumentID is expressed in.

**Possible values:**

* `8` : Exchange symbol.

**54 - Side** `char` *required*

Side of the order. Must match the side of the order being cancelled.

**Possible values:**

* `1` : Buy.
* `2` : Sell.

**60 - TransactTime** `UTCTimestamp` *required*

Time of the business event in UTC, formatted YYYYMMDD-HH:MM:SS.uuu.

**Format:** UTC timestamp, YYYYMMDD-HH:MM:SS.uuu

**trailer** *required*
