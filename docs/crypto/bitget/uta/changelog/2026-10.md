# October 2026

## [October 30, 2026] Stock+: Added Estimate Max Purchase Quantity API

**New API:**

- `/api/v3/stockplus/trade/max-purchase` Get the estimated maximum purchasable quantity for Stock+ stocks and options

## [October 28, 2026] Added Financial Parameter Change WebSocket Channels

**New APIs:**

- WebSocket `instruments` Instruments channel: pushes when trading parameters or trading pair status change
- WebSocket `open-interest-limit` Open Interest Limit channel: pushes when a single-user open interest (OI) limit changes
- WebSocket `position-tier` Position Tier channel: pushes when position tier value ranges change
- WebSocket `funding-rate` Funding Rate channel: pushes the current funding rate, settlement period changes, and cash dividend events
- WebSocket `margin-loan` Margin Loan channel: pushes margin loan limit, interest-free quota, and interest discount changes, and coin listing/delisting
- WebSocket `margin-coins` Margin Coins channel: pushes margin coin status and discount rate tier changes

## [October 22, 2026] New and Enhanced REST APIs

- `/api/v3/market/margin-loans-all` Get margin loan information for all coins. The `coin` parameter is now optional. If omitted, the API returns margin loan information for all supported coins.
- `/api/v3/market/oi-limit` Get open interest position limits. Added response fields:
  - `singlePositionRatio`: Contract position ratio for a single UID;
  - `totalPositionRatio`: Combined contract position ratio for the master account and its sub-accounts.
  - Both fields are returned as decimals; for example, `0.1` represents 10%.
- `/api/v3/account/info` Get account information. Added response field `traderType`:
  - `trader`: Trader;
  - `not_trader`: Non-trader.
- `/api/v3/trade/place-order` Place an order. Added request parameters:
  - `bboLevel`: BBO order placement level, supported for limit orders only. Available values: `queue1`, `queue5`, `counterparty1`, and `counterparty5`;
  - `slippageTolerance`: Slippage tolerance for market orders only. The default is `0.02` (2%), with a supported range of [0.01, 0.05].
- `/api/v3/trade/unfilled-strategy-orders` Get current strategy orders. Added response field `marginMode`, indicating the margin mode:
  - `crossed`: Cross margin;
  - `isolated`: Isolated margin.
- `/api/v3/trade/history-strategy-orders` Get historical strategy orders. Added response field `marginMode`, indicating the margin mode:
  - `crossed`: Cross margin;
  - `isolated`: Isolated margin.
  - Note: The Create Strategy Order API already supports the `marginMode` request parameter.
- `/api/v3/market/current-fund-rate` Get the current funding rate. Added response fields:
  - `lastFundingRate`: Previous funding rate;
  - `nextFundingRate`: Next estimated funding rate;
  - `baseInterestRate`: Base interest rate;
  - `impactMarginNotional`: Impact margin notional value.
- `/api/v3/copy/futures/copy-max-transferable` Get the maximum transferable amount for a copy trading account, based on the specified coin.

**New APIs:**

- `/api/v3/public/annoucements` Get announcements (migrated from `/api/v2/public/annoucements`)
- `/api/v3/market/coins` Get coin information (migrated from `/api/v2/spot/public/coins`)

Interface:
- /api/v3/market/instruments
- /api/v3/trade/place-order
- /api/v3/trade/place-batch
- /api/v3/user/set-rate-limit-quota
- /api/v3/user/rate-limit-quota
- /api/v3/account/max-open-available
- /api/v3/trade/unfilled-strategy-orders

Changes:
- `Get Instruments`: added response fields `fullName`, `instrumentType` (`metal`/`energy`/`stock`/`etf`/`crypto`), `marketRegion`, and `isin` for traditional-finance-related trading pairs (stocks, ETFs, Reality/rtoken, etc.). The existing `symbolType` field is unchanged and continues to be returned alongside `instrumentType`.
- `Place Order` / `Batch Order`: added request parameters `requestTime` and `receiveWindow` to both the single and batch order placement endpoints, allowing a validity window to be set for order placement. If an order is received by the matching engine after `requestTime + receiveWindow`, it is canceled instead of being placed into the order book.
- `Set RateLimit Quota` / `Get RateLimit Quota`: these endpoints now also support being called directly by a sub-account using its own API Key, to set or query its own rate limit quota. The `uids`/`uid` field is not required (and is ignored) when called by a sub-account; it remains required when called by the master account. Rules are otherwise unchanged.
- `Get Max Open Available`: added request parameter `marginMode` (`crossed`/`isolated`, defaults to `crossed`). Under isolated margin mode, the `available` calculation excludes futures trial funds.
- `Unfilled Strategy Orders`: added response field `side`, aligning with the field already present in the WebSocket order push data.

## [October 13, 2026] Notice: API Adjustments for the RToken Matching Engine Upgrade

To provide deeper liquidity and a better trading experience, we will soon upgrade the matching engine for rToken (tokenized stock) trading pairs. During the upgrade, the order placement, order book, and fills endpoints will be adjusted accordingly. Please review the changes below and prepare your strategies and systems in advance.

rToken trading pairs will be migrated to the new matching engine in batches from October 14 to October 20. For the detailed migration schedule, please refer to [this article](https://www.bitget.com/support/articles/12560603897457).

### 1. Order placement

**Place Order**

- **HTTP REST:** `POST /api/v3/trade/place-order`; `POST /api/v3/trade/place-reality-order`<br/>
- **WebSocket Topic:** `place-order`<br/>

During and after the upgrade, the existing order placement endpoint URLs and parameter logic remain **fully compatible**. You can continue to use `place-order` and `place-reality-order` to place rToken orders. Note that modifying an rToken order is not supported — cancel the resting order and place a new one instead.

Once the matching engine upgrade is complete, the system will officially support smart liquidity routing via the `venue` parameter, covering two channels: internal (onshore) matching only, and the public market. In addition to the existing `gtd` time-in-force, a new `gtc` execution strategy will be supported. For rToken, `gtc` orders are valid for 90 days.

**Order Info**

- **HTTP REST:** `GET /api/v3/trade/order-info`
- **WebSocket Topic:** `order`

After placing an order, you can query the values of `venue` and `rTokenTimeInForce` via the REST order info endpoint or the WebSocket order channel.

### 2. Standard depth (order book) changes

If you use the standard depth endpoints/channels to retrieve rToken depth data, the adjustments after the matching engine upgrade are as follows.

After upgrading to the new matching system, the order book may briefly show crossed prices — this is expected behavior.

REST API

- **HTTP REST:** `GET /api/v3/market/orderbook`
- **Weekdays (market hours):** only returns level-1 (BBO) best bid/ask data.
- **Weekends (off-hours):** returns the requested number of levels based on the `limit` parameter.

WebSocket channels

- **`books1`**: pushed **at all times**, both during and outside market hours.
- **`books5` / `books50` / `books`**: pushed **only outside market hours**.

### 3. RToken depth changes

#### RToken merged depth (`reality-orderbook`)

- **HTTP REST:** `GET /api/v3/account/reality-orderbook`
- **WebSocket Topic:** `reality-orderbook`
- **Depth levels:** up to 85 levels.
- **Push frequency:** every 500ms when the depth copy has changed, or every 10s when unchanged.
- **Note:** after upgrading to the new matching system, the order book may briefly show crossed prices — this is expected behavior.

#### RToken segmented depth (`reality-orderbook-segmented`)

This upgrade introduces rToken segmented depth, to support trading use cases that need to distinguish onshore and offshore liquidity precisely.

This depth is only available for trading pairs that have completed the matching engine upgrade; pairs that have not completed the upgrade will not push data.

Note: segmented depth is scheduled to go live on October 20, 2026.

- **HTTP REST:** `GET /api/v3/account/reality-orderbook-segmented`
- **WebSocket Topic:** `reality-orderbook-segmented`
- **Depth levels:** up to 85 levels.
- **Push frequency:** every 500ms when the depth copy has changed, or every 10s when unchanged.
- **Note:** after upgrading to the new matching system, the order book may briefly show crossed prices — this is expected behavior.
- **Data structure:** in the pushed data, the `a` (Asks) and `b` (Bids) arrays are structured as follows:

  - `a[0]` / `b[0]`: price (String)
  - `a[1]` / `b[1]`: **onshore** quantity (String)
  - `a[2]` / `b[2]`: **offshore** quantity (String)

::::tip{title="Risk Notice and Recommendations"}

1. Please note the difference in depth-level push behavior between weekdays and weekends, to avoid issues caused by `books5` / `books50` not pushing during market hours.<br/>
2. To use the rToken segmented depth (`reality-orderbook-segmented`) endpoint, please contact your account manager to request whitelist access.<br/>

If you have any questions, please contact the API technical support team at any time.

::::

rToken币对将会在10月14日至10月20日分批迁移至新撮合，具体迁移计划请参考[这里](https://www.bitget.com/zh-CN/support/articles/12560603897457)；
